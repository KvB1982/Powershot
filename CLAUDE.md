# Powershot Tennis – Hinweise für Claude

3D-Tennisspiel für den Browser (PC und iPad), entstanden als Vater-Sohn-Lernprojekt.
Repository: https://github.com/KvB1982/Powershot · läuft auf GitHub Pages unter https://kvb1982.github.io/Powershot/

## Arbeitsweise

- Antworten, Code-Kommentare und Texte im Spiel auf **Deutsch**. Kommentare so schreiben, dass ein Kind mitlesen kann.
- Kein Build-Schritt: reines HTML/CSS/JavaScript (ES-Module), three.js r160 über eine Import-Map von jsDelivr.
- Commits als `KvB1982 <KvB1982@users.noreply.github.com>` auf `main`, danach pushen. `gh` ist nicht installiert.
- Nach Änderungen im Browser prüfen, nicht nur mit den Testwerkzeugen. Ehrlich sagen, was nur als Standbild geprüft wurde.

## Starten und testen

```bash
python tools/server.py          # http://localhost:8765, ohne Zwischenspeicher
node tools/sim.mjs 0 1 mittel hard 3    # Computer gegen Computer, ohne Grafik
node tools/logic.mjs            # Turnier, Karriere (3 Jahre, Ranglisten-Regeln, Freilose) und Saison (ATP Race) durchrechnen – dauert etwa eine halbe Minute
node tools/rookie.mjs           # Neuling gegen Profi auf jeder Schwierigkeit
node tools/seitenwechsel.mjs hard 10   # Seitenwechsel prüfen: nur nach ungeraden Spielen, nie nach einem Aufschlagfehler
node tools/kind.mjs 12          # Schwierigkeit nachmessen: vier künstliche Spieler (nix = macht nichts, drueckt = schlägt nur in die Mitte, zielt, uhr = schwingt wie mit der Apple Watch mit zufälliger Richtung) auf Leicht, Mittel, Schwer. Wunsch steht oben in der Datei
node tools/wichtig.mjs          # Hinweise Breakball, Satzball, Matchball, Championship Point prüfen (`wichtigerPunkt` in `js/rules.js`)
node tools/wisch.mjs            # Steuerung „Wischen“: künstliche Finger wischen, geprüft wird Schlagart, Härte, Timing, Aufschlagart, Doppeltipp
node tools/kamera.mjs           # Laufen mit der Kamera: Rechnung prüfen (ohne Kamera, mit künstlichen Körperpunkten)
node tools/ballflug.mjs hard     # Flugbahn und Absprung jeder Schlag- und Aufschlagart messen und prüfen (auch clay, grass, indoor)
node tools/aufgaben.mjs         # Aufgaben vom Team und Tennis-Quiz prüfen: jede Frage vollständig, genug Aufgaben bei jeder Turnier-Stufe, Belohnungen, Team-Stern, dazu der Lernmodus „Tennis-Wissen“ (alle Kapitel und Bilder da, Falsches kommt wieder, drei Sterne erreichbar) (die Mini-Spiele selbst brauchen einen Browser)
node tools/gelaende.mjs         # Lagepläne aller Turniergelände prüfen: alle neun Orte da, nichts steht ineinander, jede Tür zu Fuß erreichbar
node tools/sounds.mjs           # Geräusche prüfen: jede Datei aus `KLAENGE` (js/audio.js) ist da, steht mit Quelle in sounds/quellen.json und ist CC0
node tools/einlauf.mjs          # Einlaufszene vor dem Match prüfen: läuft durch alle Teile, jeder Ball fliegt über das Netz und springt im Feld auf, Spieler stehen am Ball, Steckbrief für alle 200 Spieler vollständig (`laut` zeigt jeden Schlag)
node tools/hotel.mjs            # Weg ins Hotel prüfen: bei jedem Turnier mit Fahrdienst steht ein Hotel an einer Straße und der Wagen kommt hin, bei jedem kleinen Turnier gibt es ein Städtchen mit einem Fußweg zum Hotel (`laut` zeigt jedes Turnier)
node tools/profisaison.mjs       # Profileben im Saison-Modus: 45 Saisons über je 2 Jahre, Woche für Woche nach einem Plan aus dem Saison-Planer (Punkte verteidigen, kleine Turniere, Pflichtturniere auslassen, Abrechnung, Ziele, Jahreswechsel, Gleichgewicht der Weltrangliste); `node tools/profisaison.mjs zverev 0.7 2 angriff` zeigt eine Saison Woche für Woche (Plan: vorsichtig, ausgewogen oder angriff)
node tools/spielzuege.mjs 30    # Taktische Spielzüge: Erkennen, Durchschauen, Lernen und Wirkung im Match (30 Matches Computer gegen Computer, dauert ein paar Minuten)
node tools/mocap.mjs            # Aufnahmen aus mocap/*.FBX in mocap/bewegungen.json umrechnen (--info zeigt nur an)
node tools/gang.mjs ../Police-Quest/assets/modelle/polizist.glb   # Gehen und Sprinten aus Police Quest auf unsere Figur umrechnen → assets/gang.json (ansehen: http://localhost:8765/tools/gang.html)
node tools/mixamo.mjs "<Ordner mit Mixamo-FBX>"   # Laufen, Sprint, Seitwärts-Laufen, Stehen, Hampelmann, Kniebeuge von Mixamo auf unsere Figur umrechnen → assets/lauf.json (`--info` listet alle Dateien im Ordner; braucht three in node_modules oder die schon ausgelesenen Gelenke in `<Ordner>/_powershot/gelenke/`)
```

Im eingebauten Browser der App ist `requestAnimationFrame` gedrosselt. Das Spiel deshalb über
`window.__powershot.step(n)` vorspulen (`__powershot` enthält `game`, `controls`, `settings`, `match`, `career`, `season`, `actions`, dazu `karte`, `handy`, `foto`).
Für Bilder die Szene selbst rendern und per `canvas.toDataURL()` in ein Overlay legen – Screenshots der Seite sind oft veraltet.

## Aufbau

Koordinaten: Meter, x seitlich, y hoch, z längs; Netz bei z = 0; der Mensch spielt Seite 0 (z > 0), die Kamera steht hinter ihm.
Die Figur rechnet intern in `[vor, seite, hoch]` (seite: + = Schlaghand); Linkshänder werden gespiegelt.

## iPad und iPhone (Home-Bildschirm-App)

- Das Spiel ist eine „Web-App“: In Safari https://kvb1982.github.io/Powershot/ öffnen → Teilen → „Zum Home-Bildschirm“.
  Dann startet es im Vollbild mit eigenem Symbol (`manifest.webmanifest`, `icons/`).

  Namen ersetzt: `VERSION` in `sw.js` erhöhen.
- Auf `localhost` ist `sw.js` abgeschaltet; zum Testen `http://localhost:8765/?offline` aufrufen.

- Einstellungen → „Laufen mit der Kamera“ (`settings.kamera`: `aus`, `seite`, `voll`). Die Kamera ersetzt nur das Laufen; geschlagen wird mit der gewählten Steuerung.

## Schlagarten und Drall

- Der Drall eines Balls ist `{ top, seite, drall }` in Umdrehungen pro Minute: `top` + = Topspin, − = Slice; `seite` + = Kurve nach rechts
  (in Flugrichtung); `drall` + = springt beim Aufprall nach rechts weg (Kick). Die Tabelle gilt für Rechtshänder, `match.js` spiegelt für Linkshänder.
- Eine Steuerung gibt beim Schlag `type` an (`drive`, `flach`, `topspin`, `slice`, `drop`, `lob`), beim Aufschlag `art`
  (`gerade`, `slice`, `kick`, `unten`; ohne Angabe: erster gerade, zweiter Kick). Zusätzlich darf sie in `schlag` eigene Zahlen mitgeben,
  die über die Tabelle gelegt werden, z. B. `{ type: 'drive', schlag: { top: 3400, tempo: [28, 28] } }` – gedacht für die Apple Watch.
- Stoppball und Aufschlag von unten haben kein festes Tempo, sondern `bogen` (Höhe über dem Netz); `solveBogen` sucht das Tempo dazu.

## Steuerung auf dem Turniergelände (seit 21.11.2026, Wunsch von Kristian: „komplett vom Reitturnier übernehmen“)

- Einstellungen → „Steuerung auf dem Turniergelände“ (`settings.gelaende`: `reit` = Standard, `frei`; `Anlage.artSetzen`, `this.art`, `reit()` in `js/anlage.js`).
- `reit` = wie auf dem Pferdehof im Reitturnier (`js/hof.js`, `js/spiel.js` dort), Zahlen `REIT_…` oben in `anlage.js` sind von dort abgeschrieben: Ein Finger ist immer der Steuerknüppel (12 Bildpunkte tot, 70 = volles Tempo, links/rechts und vor/zurück einzeln gerechnet), Pfeiltasten oder WASD. Zwei Finger gehören der Kamera (jeder Finger dreht 0,004 und neigt 0,003 pro Bildpunkt, kneifen zoomt; die Kamera klebt ohne Nachziehen an den Fingern; ein Finger, der danach liegen bleibt, läuft nicht los). Rechte Maustaste ziehen, Mausrad (mal 1,12 / 0,89 je Raste), Tasten Q/R (Stufen von 22,5°), T/G und +/− (mal 0,8 / 1,25), M = Übersicht. Knöpfe rechts in zwei Spalten: 🗺️ 🏷️ · ⟲ ⟳ · ＋ － · ▲ ▼ (neigen, `KNOPF_NEIG`) · Tageszeit, Wetter · 📷. Start: 45° von oben, 18,4 m weg; 5 m bis zur Übersicht. Die Kamera bleibt immer bei der Figur: kein Schieben mit drei Fingern, kein 🎯, kein Doppel-Tipp.
- `frei` = die alte Steuerung mit freier Kamera (drei Finger, mittlere Maustaste, Umschalt + ziehen, Doppel-Tipp, 🎯, Taste F), dazu die neuen Knöpfe ▲ ▼.
- Anders als im Reitturnier und mit Absicht geblieben: Ein kurzer Tipp schickt die Figur los (dort löst er die Tätigkeit aus), Radar und Lageplan, in der Übersicht schaut die Kamera auf die Mitte des Geländes (dort auf die Figur – unsere Gelände sind viel größer), die Kamera rückt vor Gebäude, die im Weg stehen, und die Übersicht geht so weit weg, wie das Gelände groß ist (dort fest 150 m).
- Kasten unten (seit 21.11.2026, Kristian: „verdeckt fast alles, am besten ein- und ausblenden“): Unten liegt nur noch eine schmale Leiste (`.leiste`: 📋 Aufgaben mit Zahl der offenen, 🧭 Hinlaufen, ❓ Hilfe; `anlageAuf`, `actions.anlageAuf`). Darüber erscheint höchstens ein Kasten: was man aufgeklappt hat, oder der Ort, an dessen Tür man steht (mit ✕ wegzutippen, `anlageWeg`, `actions.anlageZu`; kommt wieder, wenn man neu an eine Tür tritt). Nur der Zufall am Morgen bleibt stehen, bis man gewählt hat. Das Fenster bei Hotelfahrt und Städtchen (`hotelZeigen`) ist unverändert.

## Steuerung „Wischen“ (`settings.control = 'wisch'`)

- Zweite Touch-Steuerung neben `touch` (die bleibt, wie sie ist). Geschlagen wird nur mit einem Wisch; ausgewertet wird beim Loslassen (`wischHoch` → `wischFertig` in `js/controls.js`).
- Richtung = Zeitpunkt, derselbe Code wie beim Controller/der Uhr (`padAt`, `timingZiel`; `match.js` behandelt `wisch` wie `controller`: kurze Frist nach dem besten Moment, Volleys auch bei Bällen ins Aus). Früh = cross, spät = longline: `match.js` setzt vor jedem Schlag `controls.schlagSeite` (+1 = Ball rechts von dir, −1 = links), bei −1 läuft die Ziellinie von rechts nach links. Das gilt auch für Controller und Uhr. Das Fenster beim Wischen ist länger als beim Controller (`WISCH_FRUEH` 0,46 s, `WISCH_MITTE` 0,23 s, `WISCH_HALTBAR` 0,8 s, `WISCH_SPAET` 0,18 s = `SPAET_WISCH` in `match.js`; Controller: `TIMING_…` 0,32/0,16, 0,5 s, 0,12 s).
- Schlagart = Steilheit des Wischs (`wischArt`, links/rechts egal): ↑ `topspin`, ↗ `drive`, → `flach`, ↘ `slice` lang, ↓ `slice` kurz (Tiefe 0,45; langsamer als `WISCH_STOPP` = `drop`). Härte = Tempo des letzten Stücks (`WISCH_FENSTER`) in Bildschirmhöhen pro Sekunde (`WISCH_LANGSAM` … `WISCH_SCHNELL`).
- Zwei Finger im Ballwechsel: hoch = Lob, runter = nichts. Doppelt tippen (überall) = ans Netz und zurück (`netzWechsel = 'wechsel'`). „Zwei Finger hoch = ans Netz“ gilt nur noch in `touch`.
- Aufschlag: ↑ gerade, ↓ Slice, zwei Finger ↑ Kick, zwei Finger ↓ von unten; seitliche Neigung des Wischs = Richtung (`WISCH_SCHRAEG`). Die Geste überstimmt die Aufschlag-Knöpfe.
- Laufen: Mit Laufhilfe „Voll“ (`controls.laufhilfe`, setzt `app.js`) gibt es beim Wischen keinen Joystick, der ganze Bildschirm ist zum Wischen da. Sonst Joystick links (erste 42 % der Breite), aber erst nach `STICK_AB` 0,22 s; ein Wisch dort, der kürzer als `WISCH_KURZ` 0,4 s dauert, zählt als Schlag. Grund: Bei der Rückhand wischt man gern links – früher wurde das zum Joystick, der Schlag fehlte und die Figur lief vom Ball weg.
- Geprüft: `tools/wisch.mjs` und im Test-Browser mit künstlichen Finger-Ereignissen (auch zwei Finger). Nicht geprüft: echtes iPad, echte Finger – alle `WISCH_…`-Zahlen sind geschätzt.

## Taktische Spielzüge (optional)

- Einstellungen → „Taktische Spielzüge“ (`settings.spielzuege`: `aus`/`an`, Standard `aus`). Training → „Spielzüge lernen“ öffnet das Spielzug-Buch (`actions.spielzuege` in `app.js`).
- Ein Spielzug ist eine Folge von 2–3 eigenen Schlägen (`ZUEGE` in `js/spielzuege.js`). Alles wird aus Sicht des Schlägers beschrieben: `u` seitlich (+ = rechts), `d` Tiefe hinter dem Netz.
  `match.js` baut bei jedem Schlag die Merkmale (`zugSchlag` in `launch`: wo der Ball landen wird, wo der Gegner steht, Schlagart) und fragt den `ZugZaehler` der Seite.
- Wirkung im Match (nur gelernte Spielzüge, `cfg.spielzuege = { an, stufen }`): Der Gegner bekommt `druck` – er reagiert später (`ZUG_REAKTION`), sein nächster Schlag streut mehr (`ZUG_STREUT`)
  und ist langsamer (`ZUG_SCHWACH`), einen Lob kann er nicht schmettern; man selbst trifft den Rest des Punkts genauer (`ZUG_SICHER`). Ein angefangener Spielzug wirkt schon ein wenig (`TEIL`). Der Punkt wird nie ausgewürfelt.
- Durchschauen: Der Zähler merkt sich die letzten 6 fertigen Spielzüge. Wiederholungen wirken schwächer (schneller bei einem Gegner mit viel Taktik); ab `wirkung` ≤ 0,25 reagiert der Gegner sogar früher. Nur ein Spielzug pro Punkt zählt.
- Lernen: Spielzug-Training = `cfg.lernen = id` (läuft als `mode: 'match'` mit festem Aufschläger, Trainer spielt sicher in die Mitte, 8 Versuche). `match.zugStand()` liefert Schritt und Zielfeld;
  `game3d.js` zeichnet das grüne Feld (`zugFeld`), `app.js` den Kasten `#zugBox` mit Tipp zur Steuerung (`ZUG_TIPP`). 3-mal geschafft = gelernt; Sterne nach Erfolgen im Match (`STUFEN`). Schwere Spielzüge sind gesperrt, bis genug gelernt sind (`ab`).
  Spielstand: localStorage `powershot.spielzuege.v1` (gilt für alle Spielmodi gemeinsam, nicht pro Karriere).
- Computergegner: bis zu drei Lieblings-Spielzüge aus den Fähigkeiten berechnet (`lieblingsZuege`, nicht bei echten Spielern nachgeschaut). Er nimmt sich pro Punkt manchmal einen vor (`zugPlan`, `zugWunsch`), spielt aber nur passende Schritte mit Absicht.
- Ans Netz: `Controls.takeNetz()` liefert `'vor'`, `'zurueck'` oder `'wechsel'`; `match.netzWunsch()` setzt `netRush`. Touch: zwei Finger gleichzeitig nach oben/unten wischen (`ZWEI_…` in `controls.js`), geht auch schon vor dem Aufschlag.
- Quellen der Spielzüge: Craig O'Shannessy / Brain Game Tennis („First 4 Shots“: etwa 70 % der Punkte enden nach höchstens 4 Schlägen), topspinpro.com (Patterns), Rive/Williams „Tennis Skills & Drills“ (Human Kinetics). Alle Zahlen im Spiel (Zielfelder, Stärke, Wirkung) sind geschätzt.
- Geprüft: `tools/spielzuege.mjs` und der Test-Browser (Buch, Training „Aufschlag + 1“, Zwei-Finger-Wischen mit künstlichen Finger-Ereignissen). Nicht geprüft: von Hand gespielt, echtes iPad, ob jeder Spielzug mit jeder Steuerung gut zu schaffen ist
  (Slice und Stoppball gehen mit der Maus-Steuerung „Klassik“ gar nicht; „Inside-out“ verlangt, mit dem Joystick selbst um den Ball zu laufen).

## Saison: Profileben (einen fertigen Profi übernehmen)

- Leitgedanke: In der Karriere muss man sich alles verdienen. Der Saison-Profi hat schon alles – dafür erwarten alle etwas von ihm.
- Die Saison läuft Woche für Woche (`PS.jetzt(s)` sagt, was dran ist: `gross`, `klein`, `frei`, `ende`). In einer freien Woche (23 im Jahr) geht genau eine Sache: ein kleines Turnier (ATP 500/250 aus `kleinetour.js`, hinter Platz 50–110 auch das größte Challenger) oder Urlaub, Trainingsblock, Sponsoren-Termin, Gegner studieren, Tennistag für Kinder.
- Ablauf in `app.js`: `actions.saisonPlay` (groß) oder `actions.saisonKlein` (klein) → `PS.turnierStart` / `PS.kleinStart` → Turnier-Ansicht (`saisonVorMatch`: Bilanz, Frische, Erwartung, „Was heute wirkt“) → „Erst auf die Anlage“ (gleicher Code wie Karriere über `lebenC()` / `ichJetzt()`) → Match → `PS.matchGespielt` → Abend-Auswahl → `PS.turnierFertig` (Abrechnung in `seasonTournamentDone`) → auf der Saison-Seite der Kasten „freie Woche“ (`actions.saisonWoche`).
- Belastung: Jedes Match kostet Frische (`matchLast`). Massage und Schlaf auf der Anlage gleichen höchstens einen Teil davon aus (`LAST_BLEIBT`), richtig erholt man sich nur in Wochen ohne Turnier (`erholung`, Urlaub am meisten). Müde spielen und 6 Turnierwochen am Stück erhöhen die Gefahr für Beschwerden und Verletzungen (`koerperWoche`).
- Pflicht (`auslassFolgen`): 4 Grand Slams und 8 Masters, Monte-Carlo nicht. Ausgelassen = Vorjahres-Punkte weg; 1. Mal im Jahr ohne Grund nur Verwarnung (Sponsoren-Laune −6), 2. Mal Geldstrafe (halbes Sponsorengeld eines Turniers, mindestens 20.000 $), ab dem 3. Mal doppelt und steigend, dazu Sponsoren-Laune und Medien-Druck. Mit Beschwerden oder Verletzung entschuldigt (Attest). Top 30: 4 ATP-500-Turniere im Jahr (Monte-Carlo zählt mit), sonst 30.000 $ je fehlendem am Jahresende. Die Regeln sind echt (dort: Null-Punkte-Ergebnis und Geldstrafe), Verwarnung und Höhe der Strafen sind ausgedacht.
- Saison-Planer (Reiter, `saisonPlanerHtml`): Jahres-Streifen, je Woche Plan und Frische-Vorschau (`PS.vorschau` rechnet mit so vielen Matches, wie man es vom Platz erwartet), Hinweise des Trainers, drei Vorschläge (`PS.AUTO`). Der Plan verpflichtet zu nichts („📌 in deinem Plan“ auf der Saison-Seite).
- Reiter: Saison · Saison-Planer · Zeitung & Rivalen · Team & Sponsoren (mit Pokalschrank) · Fähigkeiten & Körper · ATP Race · Weltrangliste · Punkte-Regeln.
- Im Match wirken (`PS.bonusListe`): Dazugelerntes (`plus`, höchstens +4 je Fähigkeit, +1 kostet 4 Punkte), Trainingsblock, Selbstvertrauen, Medien-Druck, Lieblings-/Angstgegner (Bilanz, ±2 Mental), Gegner-Studium, Beschwerden, Turniertag, Abend, Frische. Der Trainer gibt hier keine Pluspunkte (die echten Werte des Profis enthalten das schon), nur mehr Erfahrung.
- Alte Saison-Spielstände bekommen das Profileben beim Laden (`PS.einrichten`).

## Karriere: Geld, Reisen, Ausrüstung

- Start ungefähr auf Platz 2000 mit 4.000 $. Das Jahr hat 52 Wochen (`js/kalender.js`, echter ATP-Kalender 2026). Jede Woche wählt man: ein Turnier der Woche, Liga-Spiel, Tennisstunden geben, Pause/Urlaub oder (nur in der Off-Season im Dezember) Saisonvorbereitung.
  `career.js`: `angebot`, `zugang` (Platz-Grenzen, Wildcards), `reiseKosten`, `sponsorGeld`, `startTournament`, `matchGespielt`, `finishTournament`, `wocheOhneTurnier`.
- Weltrangliste nach ATP-Regelbuch 2026: Jeder Spieler hat eine Liste von Ergebnissen `c.erg[id] = [{ a, p, k }]` (`a` = Woche durchgezählt, `k` 1 = Pflichtturnier, 2 = ATP Finals). `zaehlen` rechnet: 52 Wochen, höchstens 18 Turniere, Pflichtturniere (4 Grand Slams, 8 Masters) zählen immer – auch mit 0 Punkten, wenn man mitspielen dürfte und nicht antritt –, Finals obendrauf. `race` zählt nur das laufende Jahr; `finalsFeld` = Top 8 des Race (mit Grand-Slam-Regel). Nicht eingebaut: die Pflicht der Top 30, vier ATP-500-Turniere zu spielen.
- Die Welt spielt mit (`wochenFelder`, `weltWoche`): Jede Woche verteilen sich die 200 echten Profis und 400 erfundenen Nachwuchsspieler auf die Turniere der Woche (plus ein paar unsichtbare Challenger/ITF-Turniere), alle Turniere werden ausgerechnet, alle bekommen Punkte. Zum Start werden die echten Punkte jedes Profis auf Turniere der letzten 52 Wochen verteilt (`vorjahr`). Geschätzt: wie oft jemand spielt (`SPIELT_OFT`), Tagesform (`FORM`), `CHALLENGER_DAZU`.
- Turnier über zwei Wochen (Grand Slam, großes Masters): wird in der ersten Woche ausgespielt; wer weit kommt (`ZWEITE_WOCHE`), überspringt die zweite Woche.
- Hinter den Top 200 wird die Platznummer aus den Punkten geschätzt (`KURVE` in `kleinetour.js`) – für den Spieler und die Nachwuchsspieler gleich.
- Alte Spielstände (14 Wochen, `c.points`) rechnet `vonAltemKalender` um.
- Acht Fähigkeiten statt fünf (`js/faehigkeiten.js`). Im Match (`mkPlayer` in `match.js`): Vorhand und Rückhand haben je eigene Härte und Genauigkeit (`p.p`/`p.c` gelten für den Schlag, der gerade gemacht wird); Beinarbeit = Lauftempo; Ausdauer: gerannte Meter machen müde (`MUEDE_…`, langsamer und ungenauer, nur in langen Matches spürbar) und ein Match kostet weniger Frische; Mental: bei Breakball, Satzball, Matchball streut der Schlag mehr oder weniger (`NERVEN`); Taktik: der Computergegner reagiert später (`TAKTIK_TARNT`), und der Computer selbst spielt klüger. Alle diese Zahlen sind geschätzt und nicht von Hand erspielt.
- Ausrüstung behält ihre Eigenschaften Kraft (`p`), Präzision (`c`), Tempo (`t`): `effectiveStats` legt Tempo auf die Beinarbeit und gibt Kraft/Präzision als `kraft`/`praez` mit, die im Match auf Vorhand und Rückhand wirken. Die Werte der Profis für Vorhand/Rückhand, Ausdauer, Mental, Taktik sind aus den alten fünf Werten berechnet (mit kleinen ausgedachten Unterschieden), nicht einzeln recherchiert. Alte Spielstände rechnet `vonFuenfAufAcht` um.
- Körper: `matchGespielt` zählt Matches und die niedrigste Frische der Woche, `wocheFertig` fragt `koerperWoche` (Beschwerden `c.koerper`, Verletzung `c.verletzung`, Turnierwochen am Stück `c.serie`). Eine Woche ohne Match oder der Physio auf der Anlage heilt Beschwerden. Verletzt geht nur `wocheOhneTurnier(c, 'reha')`; Pflichtturniere zählen dann nicht als verpasst (vereinfacht). Ansicht: Karriere-Reiter „Profi-Service“.
- Schuhe und Belag: Am Anfang hat man nur alte Turnschuhe (gehen auf Hartplatz und in der Halle). Für Sand und Rasen braucht man einen gekauften Schuh mit mindestens +2 Tempo auf dem Belag (`schuhePassen`, `fehltFuer`), sonst startet `startTournament` nicht (Liga ausgenommen). Wimbledon: Weiß ist Pflicht, ohne weißes Outfit kostet es weiter die Leihgebühr. `ausruestungJetzt` listet die Ausrüstung samt Sachen vom Anfang (Kasten „Das hast du gerade“ in der Übersicht).
- Frische (0–100): Matches kosten, Wochen erholen (Physio); unter 70 gibt es Abzüge. Saiten halten nur ein paar Matches und werden automatisch neu bespannt.
- Sammlung (`ausruestung.js`): Seltenheit `selten` 0–3 (`SELTEN`; macht nicht stärker), Turnier-Editionen (`EDITIONEN`, erfundene Outfits ohne Marke, nur in der Turnierwoche und mit Startrecht zu kaufen: `editionDa`), Sonderstücke für Erfolge (`SONDER`, `sonderPruefen` in `wocheFertig`), Turnier-Handtücher (`c.handtuecher`). Shop: Anprobe der eigenen Figur in 3D (`game.figurZeigen`, `CA.anprobeLook`), Reiter „Sammlung“. Im Match steht die eigene Tasche neben der Bank (`game.tascheZeigen`, aus einfachen Formen).
- Echt sind Marken, Modellreihen, Punkte pro Runde und die Turnierorte. Geschätzt sind alle Pluspunkte, Preisgelder (Größenordnung), Platz-Grenzen, Flugpreise, Löhne und Sponsorengeld.
- Marken nur als Text, keine Logos; das Spiel ist für den Privatgebrauch.

## Schwierigkeit, Erste Schritte, Hilfen (Review vom 21.11.2026)

- Schwierigkeit (`DIFFICULTY` in `js/data.js`): neu sind `aiAngriff` (wie oft der Computer einen langsamen Ball in die Mitte hart in die freie Ecke schlägt – „Chance-Ball“, Zahlen `CHANCE_…` oben in `match.js`, er schlägt ihn auch genauer) und `meReact` (so viel später läuft die eigene Figur mit Laufhilfe los). Stufe „Leicht“: Wer gar nicht schlägt, bekommt nur noch einen schwachen Hilfs-Schlag (`HILFS_SCHLAG`), danach läuft die Figur spät los (`HILFS_SPAET`) und der Computer greift an – Leicht spielt sich nicht mehr von allein. Das Ergebnis zeigt, wie oft das Spiel geholfen hat (`match.hilfsZahl`). Gemessen mit `tools/kind.mjs` (als Zverev, 12 kurze Matches): nichts tun verliert überall; nur drücken gewinnt auf Leicht fast alles, auf Mittel 59 % der Punkte (mit einem Spieler um Platz 15: die Hälfte der Matches), auf Schwer fast nichts; zielen gewinnt auf Mittel 90 %, auf Schwer 60 %. Alle Zahlen geschätzt und nur mit künstlichen Spielern gemessen, nicht von Hand gespielt – Schwer ist dadurch deutlich schwerer als vorher.
- „Erste Schritte“ (`ERSTE`, `actions.erste…` in `app.js`, Stand in `powershot.erste.v1`): vier Lektionen aus vorhandenen Teilen (Ballmaschine 8 und 10 Bälle, 6 Aufschläge, kurzes Match auf Leicht gegen den Letzten der Top 200). `startMatch` nimmt dafür `difficulty`, `length`, `hinweis`, `ohneHilfe` an; `match.training` zählt `drin` und `treffer`. Wird im Hauptmenü angeboten, bis man fertig ist oder „Kenne ich schon“ tippt.
- Hauptmenü in drei Gruppen (Spielen · Üben und Lernen · Entdecken), dazu „Was ist was?“ (`actions.neuImSpiel`, `STUFE_TEXT`). Im Match: Knopf „?“ = Spickzettel mit der eigenen Steuerung (`actions.spick`), „Match aufgeben“ braucht zwei Tipps. Freies Spiel: „Revanche“ auf dem Ergebnis. Schlagbuch: Zeile „So spielst du ihn mit deiner Steuerung“ (`SPIEL_TIPP`, `soSpielstDu`). Karriere-Übersicht: Kasten „Dein nächster Schritt“; neue Karrieren beginnen 2027 (wie der Saison-Modus), mit 3D-Vorschau der Figur beim Erstellen. Gelände: Kasten unten einklappbar (`anlagePanel`), 🔒 an Orten, die es bei kleinen Turnieren nicht gibt. Nachwuchsspieler heißen im Turnierbaum „T. Nachname“.
- Geprüft: `tools/kind.mjs`, die anderen Prüfwerkzeuge, `profile.js` in node, und im Test-Browser als Standbilder (Hauptmenü, Was ist was, Wer spielt mit Anlegen und Wechseln, Erste Schritte Lektion 1, Match-Anfang ohne blaue Wand, Spickzettel, Aufgeben, Ergebnis mit Revanche (angetippt), Neue Karriere, Shop, Gelände am Turniertag). Nicht geprüft: von Hand gespielt, echtes iPad, Datei sichern und laden im Browser und in der iOS-App (dort geht das Herunterladen vielleicht nicht), Lektionen 2 bis 4 bis zum Ende.

## Tempo und Action (seit 21.11.2026, Wunsch von Kristian: „Ball zu langsam, mit der Uhr zu schwer, Punkte zu machen“)

- Bälle mit Absicht schneller als echt (`tempo` in `js/schlaege.js`: Topspin 28–46 m/s, gerader Schuss 32–52, vorher 24–42 und 27–47; `kraft` 0,5 = ein lockerer Schlag hat nur das halbe Tempo), Aufschlag bis 227 km/h (`AUFSCHLAG_…` in `match.js`). Dazu passend schnellere Beine (`LAUF_…` 4,6–7,3 m/s, `ANTRITT_…`). Abgestimmt nur Computer gegen Computer: Ballwechsel etwa so lang wie vorher (Top 2: 8,9 statt 8,4 Schläge), `tools/kind.mjs` fast unverändert. Wer das Balltempo ändert, muss die Beine mitziehen.
- Einstellungen → „Spieltempo“ (`settings.tempo`: `echt` 1, `schnell` 1,1 = Standard, `turbo` 1,22; `TEMPO_MAL` in `app.js`): Die Zeit im Match läuft schneller (Ball, Spieler, Bewegungen zusammen). Die Steuerung rechnet in echter Zeit weiter, ihre Zeitfenster werden also nicht kürzer. `__powershot.step(n)` rechnet immer ohne Spieltempo.
- Im Bild (`game3d.js`, Zahlen `SCHWEIF_…`, `WUCHT_…`, `RUCK`, `BLITZ_ZEIT` oben): Schweif hinter dem Ball als Band (heller bei Tempo), bei harten Schlägen ein Ring am Treffpunkt und ein kurzer Kamera-Ruck, bei eigenen harten Schlägen die km/h-Anzeige (`schlagTempo` in `app.js`, 🔥 ab etwa 143 km/h).
- Schwingen (Uhr, iPhone-Schläger, Joy-Con; nur echte Schwünge, keine Tasten): `schwungHaerte` (schon ein sanfter Schwung hat Härte 0,5, mittlere fast voll), `schwungRichtung` (eher in die Ecken), harte Schwünge tiefer, Streuung mal `SCHWUNG_GENAU` 0,7, der Computer reagiert `SCHWUNG_UEBERRASCHT` 1,8-mal so spät. Zeitfenster Controller/Uhr länger: `TIMING_FRUEH` 0,38, `TIMING_MITTE` 0,19, `TIMING_SPAET` = `SPAET_FENSTER` 0,15, `PAD_HALTBAR` 0,6. Die Uhr selbst (Swift, volle Kraft ab 5 g) ist unverändert.
- `physics.js`: Der Schlag-Löser rechnet jetzt im selben Schritt wie der Ballflug und bis genau zur Bodenberührung – sonst landeten die schnelleren Bälle bis 23 cm neben dem Ziel.
- Geprüft: Prüfwerkzeuge, ein künstlicher Uhr-Spieler (als Zverev auf Mittel: 138 statt 5 eigene Winner in 24 kurzen Matches, Punkte-Anteil 78 % statt 72 %; mit einem Spieler um Platz 60 kaum leichter) und Standbilder im Test-Browser mit nachgemachtem Uhr-Schwung. Nicht geprüft: von Hand gespielt, echte Uhr, flüssige Bewegung (Ruck und Schweif nur als Standbild), ob das Spieltempo wirklich 1,1-mal läuft (der Test-Browser ist zu langsam zum Messen). Alle Zahlen geschätzt.

- Gehen und Sprinten (seit 21.11.2026): Beim Seitenwechsel, auf dem Turniergelände, im Städtchen und bei der Siegerehrung (überall, wo `st.walk` gesetzt ist) spielt die Figur zwei Aufnahmen aus Police Quest ab (`assets/gang.json`: `walk` 1,04 m/s, `sprint` 3,49 m/s; von Kristian mit DeepMotion SayMotion erzeugt, mit `tools/gang.mjs` auf unsere Maße umgerechnet – nur Richtungen der Glieder, Längen von unserer Figur). Je nach Tempo wird gemischt (`laufK` in `js/avatar.js`): Seitenwechsel mit 1,5 m/s ist Gehen mit einem Schuss Laufen, das Joggen auf dem Gelände mit 4 m/s ist der volle Sprint. `?altergang` in der Adresse zeigt zum Vergleich die gebauten Bewegungen (`GANG`, `JOGGEN` – bleiben als Rückfall, wenn die Datei fehlt). Im Ballwechsel läuft die Figur weiter mit dem gebauten Schrittzyklus (dort schaut sie zum Netz und läuft seitwärts, dazu passen die Aufnahmen nicht). Nur als Standbilder im Test-Browser angesehen (`tools/gang.html` von der Seite und schräg von vorn bei 1,0 / 1,5 / 2,6 / 4 m/s, dazu ein Bild auf dem Gelände Wimbledon), nicht in flüssiger Bewegung, nicht auf dem iPad. Die Arme hängen beim Gehen etwas breit (der Polizist trägt einen Gürtel mit Ausrüstung). Schläger tragen (`TRAGEN` in `js/avatar.js`, nach Kristians Rückmeldung „wie eine Pfanne“): Der Schläger hängt mit der Kante nach unten schräg nach vorn neben dem Bein (Bespannung schaut zur Seite), hängt am Unterarm und schwingt träge mit; der Schlägerarm schwingt nur gut halb so weit wie der freie (`armRuhig`). Geprüft in Nahaufnahmen (`tools/gang.html`, Blicke „nah an der Schlaghand“, „nah von vorn“, „schräg von hinten“) im Stehen, Gehen und Sprinten – als Standbilder. Beim Mischen in mittlerem Tempo können die Füße etwas rutschen.
  Liegt in `mocap/bewegungen.json` eine eigene Aufnahme `walk` (Eintrag in `tools/mocap.mjs`, mit einer echten Datei noch nicht erprobt), geht sie vor. Slice-Topspin-Unterschiede bei einhändigen Spielern fehlen.

Nur die Gesetzten (`def.setz`) stehen fest im Baum, der Rest wird gelost (`createTournament`). Wer nach einem Freilos sein erstes Match verliert, bekommt die Punkte der ersten Runde.
